# Requirement traceability: FRD v1.0 to implementation

Status of the **Phase 1 MVP vertical slice** (FRD §13) as implemented in `backend/` and `frontend/`.
"Done" means the stated acceptance behaviour is covered by an automated test. It does
**not** mean the release gates in §11 are met: those need real permissioned documents,
PostgreSQL row-level security (RLS), and pilot measurements.

| ID | Requirement | Status | Where / tests |
|----|-------------|--------|---------------|
| FR01 | Project access | **Done (app layer)**. Every route resolves the live membership. Non-members and missing objects get the same `AUTH_FORBIDDEN`. Revocation takes effect on the next request. PostgreSQL RLS enforces the same boundary at the database layer (NF01). | `services/access.py`; `test_second_organisation_cannot_access_any_object`, `test_revoked_member_loses_access_immediately` |
| FR02 | Project configuration | **Done**. Changes create config revisions that record actor and time. Polygons are validated with diagnostics. The project CRS is never assigned to input data. | `services/projects.py`; `test_config_revisions_*`, `test_project_crs_is_not_assigned_to_input_data` |
| FR03 | Resumable uploads | **Done**. Upload sessions honour an Idempotency-Key and track confirmed byte ranges. Each chunk and the whole file are SHA-256 checked. Uploads require a rights confirmation and expire after 7 days. Quarantine works. The malware scanner is a **stub** that only detects the EICAR test signature; it must be replaced with ClamAV or a managed scanner. | `services/uploads.py`; `test_interrupt_at_40_percent_and_resume`, `test_malware_quarantine_prevents_parsing` |
| FR04 | Duplicates and versions | **Done**. Identical bytes in the same project prompt reuse. A replacement must be named explicitly and links a new version. Older evidence still opens. Dedup is never visible across tenants. | `test_duplicate_bytes_*`, `test_no_cross_tenant_dedup_visibility`, `test_replacement_marks_prior_records_stale_*` |
| FR05 | Processing jobs | **Done (inline executor)**. Each page is an idempotent task with 3 retries and backoff. Jobs support selective retry, cancel and a manifest. A durable queue and sandboxed workers are still to come (NF05). | `services/processing.py`; `test_failed_page_retry_without_duplicate_candidates` |
| FR06 | Document and OCR extraction | **Done for printed scans**. Text-layer PDFs give page text and character-offset anchors. Scanned pages, or pages with fewer than 12 extractable characters, are rendered with PDFium at 300 DPI and read with Tesseract. Tesseract runs as a subprocess with a timeout, and orientation detection corrects rotated pages. OCR anchors carry word boxes in PDF points (origin top-left) and the lowest word confidence. Every OCR candidate needs the reviewer to acknowledge `OCR_VERIFY_AGAINST_IMAGE`. `OCR_LOW_CONFIDENCE` is raised for uncertain figures, poor pages are flagged, and blank or handwritten pages are flagged `OCR_NO_TEXT` for manual entry. If Tesseract is missing, pages are flagged `OCR_REQUIRED`; OCR timeouts are retried. **Limits:** mixed pages (a text layer plus a scanned table image on the same page) use only the text layer; table structure is not reconstructed; text-layer PDFs still have no word boxes. | `services/ocr.py`, `services/processing.py`; `test_ocr.py`, `test_page_without_text_is_flagged_*`, `test_pdf_candidates_link_to_page_regions` |
| FR07 | Structured import preview | **Done**. CSV and XLSX support delimiter, encoding, sheet and header choice, and column and unit mapping. The preview reports row counts and issues. Commit is keyed to the preview hash and is idempotent. Formulas are never executed: cached values are used, and a missing cached value must be supplied. Macros and external links are rejected. | `services/imports.py`; `test_import_preview_*`, `test_xlsx_formulas_*`, `test_macro_workbook_rejected` |
| FR08 | Candidate extraction | **Done**. Candidates are schema-constrained, record their method and uncertainty, and keep field-level anchors. PDF pages go through a deterministic line-pattern extractor first. Lines it cannot read that look like assay rows (a sample ID followed by figures) go to the model-assisted extractor when the project's processing policy allows it: the model returns JSON under a strict schema, giving each cell's line and verbatim text; `check_model_rows` rejects anything not printed character for character on the cited line, partial numbers, reformatted or computed figures, results off their sample's line, non-symbol analytes and duplicates. Invalid output is rejected, **retried once with the rejection reasons, then routed to manual review** (`EXTRACTION_MANUAL_REQUIRED`). Outages and refusals flag the page for manual entry, and without permission the lines are flagged `UNPARSED_TABLE_LINES` (never silently skipped). Accepted rows are anchored to each cell, carry `MODEL_EXTRACTED_VERIFY` (plus the OCR warning on scans), have `high` uncertainty and go through normal validation and second-person review. Runs are audited with model, usage and counts but no evidence text. Extraction accuracy against the §11 targets is **not measured yet**. | `services/processing._model_extraction`, `check_model_rows`, `services/llm.AnthropicAnswerProvider.extract_assays`; `test_model_extraction.py` |
| FR09 | Scientific validation | **Done**. Validation uses versioned unit, analyte and rules registries. LT/GT qualifiers are preserved. Ambiguous or unknown units, decimal commas, BDL without a limit and the negative-value convention are all blocked. Oxide factors are gated by approval. Critical issues block approval; warnings must be acknowledged. | `science/`, `services/records.validate`; `test_science.py`, `test_critical_issue_blocks_and_warning_needs_ack` |
| FR10 | Coordinate validation | **Done**. The CRS and axis order must be confirmed. The PROJ pipeline and accuracy are kept. A missing datum grid blocks the transform. Points outside the boundary are flagged, not moved. Missing coordinates never become (0,0). | `science/crs.py`; `test_coordinate_blocks`, `test_known_utm_fixture_*`, `test_outside_boundary_flagged_not_moved` |
| FR11 | Human review | **Done (API and UI)**. Revisions are immutable and corrections show a before/after diff. Self-approval is blocked. Optimistic locking returns 409. Bulk review reports failures per row. The review workspace shows evidence and fields side by side, supports bulk approval of homogeneous batches, and has keyboard navigation. | `test_reviewer_corrects_decimal_*`, `test_concurrent_edit_*`, `test_bulk_partial_failure_*` |
| FR12 | Identity and conflicts | **Done**. Competing results are grouped by sample, analyte and basis. They are never auto-merged and a governing result is never auto-selected. Choosing one needs an approved result and a written rationale. A new member re-opens the decision without replacing the current governing result. Agreeing duplicates count once. | `services/records.refresh_conflicts`; `test_revised_certificate_*`, `test_resolving_conflict_*`, `test_agreeing_certificates_count_once` |
| FR13 | Source viewer | **Done**. The API returns the anchor locator, raw value and page context, plus a short-lived HMAC-signed view link that is re-authorised on every use. The UI highlights the anchored text on the page, shows the exact cell and raw value, and opens the original page (PDF `#page=`). Because the link is signed and short-lived, it works in a new tab; it is refused if the request identifies as a different user. | `services/exports.anchor_view`; milestone tests |
| FR14 | Search and filters | **Partial**. Exact sample-ID and certificate search, full-text page search, and record filters for analyte, lab, campaign, method, status and missing coordinates all work. Semantic search reports `unavailable` and falls back as specified. Filtering by date is not yet supported. | `services/queries.search` |
| FR15 | Project map | **Done**. Only approved points are returned as GeoJSON, with a bbox filter, an unmapped count and a censored-value flag for symbolisation. The MapLibre UI draws censored results with their own symbol and shows uncertainty circles. Rectangle selection scopes threshold questions, the table and map selection are linked, and unmapped samples are listed. There is a table-only mode and a basemap-failure fallback. | `services/queries.features`; `test_map_shows_*` |
| FR16 | Numerical query tools | **Done**. Tools are typed, allowlisted and read-only: threshold, missing coordinates, and methods and units. Threshold queries use three-valued censored comparison. Mixed basis triggers a clarification. Snapshots are frozen, reproducible and can be re-run. No SQL is generated. | `services/queries.py`; milestone tests, `test_tools_are_allowlisted`, `test_mixed_basis_*` |
| FR17 | Evidence-based answers | **Done**. Numerical and categorical questions go to the deterministic tools. Narrative questions go through these steps: (1) keyword retrieval over authorised page text (element-name synonyms only; minerals are never mapped to elements); (2) a provider-neutral language-model adapter (`services/llm.py`; default Claude via the Anthropic SDK, with passages sent as `search_result` blocks and citations required); (3) a deterministic guard (`services/answers.py`) that keeps a statement only if its citations resolve to passages that were sent and every figure in it appears in the cited text; (4) a frozen snapshot that goes stale when evidence changes. Uncited or unsupported text is withheld and counted; if nothing survives, the answer is explicitly "insufficient evidence". Provider failure or refusal leaves search and the tools available. The adapter's request shape and parsing are tested against real SDK types with a stubbed transport. Answer quality against the FRD §11 targets is **not measured yet**: it needs the gold question set, and there is an opt-in live test (`AJGEM_LIVE_LLM=1`). | `services/llm.py`, `services/answers.py`; `test_answers.py` |
| FR18 | Targets and checklists (P1) | Not started | |
| FR19 | Correction and stale evidence | **Done**. Corrections create revisions. Approvals, governing-result changes and source replacement mark cached answers and records stale. Historical snapshots can still be re-run. | `test_resolving_conflict_*`, `test_replacement_marks_prior_records_stale_*` |
| FR20 | Exports | **Done (CSV, GeoJSON)**. Exports need a separate grant, which is checked again at download. Each export is a ZIP with data and a manifest. The manifest records filters, units, comparators, record and revision IDs, anchors, source SHA-256 hashes, the unmapped count and unresolved counts. Viewers get coordinates withheld. CSV formulas are escaped. GeoPackage export is P1. | `services/exports.py`; `test_export_with_provenance_manifest` |
| FR21 | Audit | **Done**. Events are append-only and written in the same transaction as the change, so a logging failure rolls the change back. Updates and deletes are refused at the ORM layer. Only admins can read the audit log. Database-level immutability is still to come (revoked UPDATE/DELETE grants). | `services/audit.py`; `test_audit_reconstructs_history_and_is_immutable` |
| FR22 | Retention and deletion | **Done.** Administrators can delete a document version (`DELETE /versions/{id}`) or a whole project (`DELETE /projects/{id}`). Each requires a reason and the name typed out to confirm. Deletion removes the original files (an object shared with another live version in the organisation is kept, checked by the owner role across projects), extracted page text, anchors, derived records and revisions, conflict memberships, import previews, jobs and upload sessions. Historical answers lose the removed rows and excerpts and show a deletion notice (`evidence_removed`). Exports containing the source are withdrawn, their files erased, and downloads return 410. What remains is a `DeletionRequest` tombstone with counts, content hashes and the backup-expiry date (35 days by default, or `retention_policy.backup_days`), plus the audit events with their details scrubbed by the owner role. There are no embeddings or caches yet; when they are added, deletion must purge them too. | `services/deletion.py`, migration `0003`; `test_deletion.py` (SQLite and PostgreSQL), and a browser check of the admin UI |

## Screens (FRD §8)

All nine screens in the FRD §8 inventory are implemented in `frontend/src/pages/`. They are verified by unit tests (`npm test`) and by `frontend/e2e/milestone.cjs`, a browser walkthrough of the §13 milestone with the real backend:
1. An analyst maps and imports a CSV, and the `ppt` result is flagged critical.
2. A reviewer approves records and saves a correction. Self-approval is blocked in the UI.
3. A second reviewer approves the correction.
4. The certificate conflict is resolved with a rationale.
5. The earlier answer shows as stale, and the fresh answer excludes the superseded result.
6. The evidence drawer opens the exact cells, and an export is downloaded.
7. A user from another organisation sees no projects.

Not yet done: a full WCAG audit (keyboard paths exist and contrast is checked visually only), offline drafts (P2), and the PDF word-box overlay (needs word boxes from OCR).

## Non-functional requirements

| ID | Status |
|----|--------|
| NF01 Isolation | **Done.** Isolation is enforced twice, once in the application and once in PostgreSQL row-level security (`ajgem/rls.py`). The application checks every route, and object keys are scoped per tenant. RLS is enabled and forced on all 20 tables. The API runs as a separate `NOBYPASSRLS` runtime role whose context (`app.user_id`, `app.org_id`) is set per transaction in `load_principal`. Organisation-scoped tables match on organisation. Project content additionally requires a live membership through `ajgem_visible_projects()`, and job tasks are visible only through a visible job. With no context the runtime role sees nothing. The runtime role has no UPDATE or DELETE on `audit_events`. The owner role is the documented bypass, used only for schema setup and maintenance tools, and the server refuses to start if its runtime role bypasses RLS. Tests: `test_rls.py` (9 database-level tests with app checks bypassed, plus a mutation check showing they fail without the policies), and the full suite also runs on PostgreSQL in CI. **Still to do:** adversarial tests covering prompt injection against isolation, and RLS for out-of-band workers once a queue exists. Workers must set the same context. |
| NF02 Identity | **Done (OIDC).** `AJGEM_AUTH_MODE=oidc` signs users in with the organisation's identity provider using authorisation code + PKCE, a public client, and state and nonce checks (`frontend/src/lib/auth.ts`). The API then verifies the ID token sent as a bearer token (`ajgem/auth.py`): signature against the provider's published keys (RS/ES/PS only, never `none` or HMAC, re-fetched on key rotation), issuer, audience, expiry and a maximum session age (12 hours by default). Accounts are never created by signing in: the first sign-in links the provider subject to the existing account with the same verified email, and the subject alone is used afterwards. **MFA** is read from `amr` (or a configured `acr`) and is required for administrator and reviewer operations (manage, review, resolve conflicts, audit), returning `MFA_REQUIRED` with a re-sign-in prompt. **Revocation** takes effect on the next request: deactivating a user, revoking a membership, or running `python -m ajgem revoke-sessions EMAIL`. In OIDC mode the development header and user picker are disabled. No secrets reach the browser bundle; the ID token is kept in session storage only. Tests: `test_auth.py` (10 tests, SQLite and PostgreSQL) and `frontend/e2e/oidc.cjs`, a browser run against a development-only mock provider, in CI. **Still to do:** each pilot's provider configuration and its MFA claim (some providers express MFA through `acr` or not at all), and refresh-token rotation (users currently re-sign-in when the ID token expires). |
| NF05 Untrusted files | Formulas, macros and external links are never executed, and file signatures are checked. **Still to do:** sandboxed parsers with CPU, memory and network limits. |
| NF14 Deployment integrity | **Done.** Dependencies are pinned. Alembic migrations (`0001` schema, `0002` RLS) run as the owner role, automatically on start-up or as an explicit step when `AJGEM_AUTO_MIGRATE=0`, in which case start-up refuses an out-of-date schema. Each migration runs in a transaction, so a failed migration leaves no partial changes on PostgreSQL. Tests cover drift detection between models and migrations (with a mutation check), downgrade and upgrade round trips (including the RLS revision), a single migration head, refusal of pre-migration databases, and stamping. CI runs the backend suite on SQLite and PostgreSQL, plus the frontend and browser checks. **Still to do:** staged releases and rollback runbooks for production. |
| NF04 Provider privacy | **Done for the answer adapter**. Each project has a `provider_policy` in its config revisions, and it defaults to off. An administrator must record the processing basis (retention, region, contract) before allowing external processing, and the change is audited. Only the excerpts retrieval selects are sent; database access and credentials are never sent. Audit events record the model, token usage and counts but not the evidence text. Still to do: per-organisation budgets and quotas (NF11). |
| Others (NF03, NF05–NF13) | Not started. These are infrastructure and pilot concerns. |

## Open verification items carried from the FRD

* The Li to Li2O factor `2.153` ships **unapproved** (`Li-Li2O-2026.11-draft`). A reviewer must activate it per organisation, and the atomic-weight source still needs independent verification (FRD §6).
* The OCR engine is Tesseract with English only. Its accuracy on real certificate layouts has not been measured: the FRD §11 targets (CER ≤2% on clean scans, ≥98% critical-field accuracy) still need the gold collection.
* The Minna-datum transforms used in Nigeria have several candidate pipelines. The system takes PROJ's best one, but it records `MULTIPLE_TRANSFORMATIONS_AVAILABLE` so the reviewer can see the choice.

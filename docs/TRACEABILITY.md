# Requirement traceability: FRD v1.0 to implementation

Status of the **Phase 1 MVP vertical slice** (FRD §13) as implemented in `backend/` and `frontend/`.
"Done" means the stated acceptance behaviour is covered by an automated test. It does
**not** mean the release gates in §11 are met: those need real permissioned documents,
PostgreSQL row-level security (RLS), and pilot measurements.

| ID | Requirement | Status | Where / tests |

| FR01 | Project access | **Done (app layer)**. Every route resolves the live membership. Non-members and missing objects get the same `AUTH_FORBIDDEN`. Revocation takes effect on the next request. PostgreSQL RLS enforces the same boundary at the database layer (NF01). | `services/access.py`; `test_second_organisation_cannot_access_any_object`, `test_revoked_member_loses_access_immediately` |
| FR02 | Project configuration | **Done**. Changes create config revisions that record actor and time. Polygons are validated with diagnostics. The project CRS is never assigned to input data. | `services/projects.py`; `test_config_revisions_*`, `test_project_crs_is_not_assigned_to_input_data` |
| FR03 | Resumable uploads | **Done**. Upload sessions honour an Idempotency-Key and track confirmed byte ranges. Each chunk and the whole file are SHA-256 checked. Uploads require a rights confirmation and expire after 7 days. Quarantine works. Scanning uses a ClamAV daemon (`AJGEM_SCANNER=clamd`, INSTREAM over TCP or a Unix socket) and fails closed: no verdict means the upload is refused with `SCAN_UNAVAILABLE` and can be retried; it is never stored unscanned. The development default only detects the EICAR test file, and the server logs a warning if it is used with organisation sign-in. | FR04 | Duplicates and versions | **Done**. Identical bytes in the same project prompt reuse. A replacement must be named explicitly and links a new version. Older evidence still opens. | FR05 | Processing jobs | **Done**. Each page is an idempotent task with 3 retries and backoff. Jobs support selective retry, cancel and a manifest. With `AJGEM_JOB_EXECUTOR=worker`, jobs are queued durably and run by `python -m ajgem worker` processes. A worker claims a job by compare-and-set on a renewable lease, runs it as the job's creator (same access checks and RLS context, so revoked access fails the job), and commits each page. A dead worker's job is resumed from the next unfinished page after its lease expires, and a job that keeps killing workers is failed after `job_max_claims`. Cancels are honoured between pages. The inline executor remains the development default. | `services/processing.py`, `services/worker.py`, migration `0005`; `test_failed_page_retry_without_duplicate_candidates`, `test_worker.py` (SQLite and PostgreSQL) |
| FR06 | Document and OCR extraction | **Done for printed scans**. Text-layer PDFs give page text and character-offset anchors. Tesseract runs as a subprocess with a timeout, and orientation detection corrects rotated pages. OCR anchors carry word boxes in PDF points (origin top-left) and the lowest word confidence. Every OCR candidate needs the reviewer to acknowledge `OCR_VERIFY_AGAINST_IMAGE`. `OCR_LOW_CONFIDENCE` is raised for uncertain figures, poor pages are flagged, and blank or handwritten pages are flagged `OCR_NO_TEXT` for manual entry. Text-layer anchors are placed on the page image when viewed: PDFium finds the same occurrence of the anchored text, and if it cannot, no outline is drawn rather than a guessed one. | `services/ocr.py`, `services/processing.py`; `test_ocr.py`, `test_page_without_text_is_flagged_*`, `test_pdf_candidates_link_to_page_regions` |

| FR08 | Candidate extraction | **Done**. Candidates are schema-constrained, record their method and uncertainty, and keep field-level anchors. PDF pages go through a deterministic line-pattern extractor first. Lines it cannot read that look like assay rows (a sample ID followed by figures) go to the model-assisted extractor when the project's processing policy allows it: the model returns JSON under a strict schema, giving each cell's line and verbatim text; `check_model_rows` rejects anything not printed character for character on the cited line, partial numbers, reformatted or computed figures, results off their sample's line, non-symbol analytes and duplicates. Accepted rows are anchored to each cell, carry `MODEL_EXTRACTED_VERIFY` (plus the OCR warning on scans), have `high` uncertainty and go through normal validation and second-person review. | FR23 | Extended inputs (P1) | **Done: DOCX frozen rendering, GeoPackage layers and raster overlays.** A `.docx` (`.docm` with macros refused) is rendered by a versioned renderer (`docx-render-v1`) into frozen page text: one line per paragraph, table rows with cells joined by ` \| `, and pages split at explicit page breaks and every 60 paragraphs. Only `word/document.xml` is read, external entities and relationships are never followed, and rendering runs in the parser sandbox. Extraction and model-assisted extraction then work as on a PDF text layer, and unreadable table rows are flagged. Citations into Word text (`doc_text` anchors, from extraction or from answers) also store a locator: the renderer, the paragraph index, offsets within the paragraph and a hash of the paragraph text. `POST /versions/{id}/rerender` renders again with the current renderer and moves every citation to its paragraph's new page and offsets. Tests: a renderer change re-paginates, and every citation still selects the same characters (checked by `verify`). **GeoPackage layers:** A `.gpkg` upload is recognised by its SQLite header and GeoPackage application id; a plain SQLite file is refused. It goes through the column-mapping import with the layer as the sheet. The file is read in the parser sandbox, read-only and immutable, with schema code untrusted and identifiers from the file quoted. | FR26 | Map georeferencing (P2) | **Done.** Scanned maps (PNG, JPEG, or a TIFF without georeferencing) become flagged overlays whose preview can be opened to read pixel positions. An analyst or reviewer enters control points (pixel column and row against map x and y in a stated CRS), and an affine transform is fitted by least squares (`affine-least-squares-v1`, pure Python). The fit reports per-point residuals, RMSE, maximum residual and pixel size. Publication is blocked with fewer than 4 points, points covering less than 10% of the image, or collinear points. Suspect points are found by leave-one-out (a plain residual test cannot catch one bad point among few). A second person (`records.review`, not the one who fitted) approves. The approved overlay stores the transform, its accuracy (RMSE plus the CRS transform) and a statement of limitations. Any control-point edit unpublishes it until reviewed again. Every step is audited, and points are never taken from OCR'd place names. | `science/georef.py`, `services/overlays.py`, migration `0011`; `test_georef.py` |

## Screens (FRD §8)

All nine screens in the FRD §8 inventory are implemented in `frontend/src/pages/`. They are verified by unit tests (`npm test`) and by `frontend/e2e/milestone.cjs`, a browser walkthrough of the §13 milestone with the real backend:
1. An analyst maps and imports a CSV, and the `ppt` result is flagged critical.
2. A reviewer approves records and saves a correction. Self-approval is blocked in the UI.
3. A second reviewer approves the correction.
4. The certificate conflict is resolved with a rationale.
5. The earlier answer shows as stale, and the fresh answer excludes the superseded result.
6. The evidence drawer opens the exact cells, and an export is downloaded.
7. A user from another organisation sees no projects.

The source viewer outlines the anchored figure on the rendered page, for OCR anchors and for text-layer anchors; page images are rendered in the parser sandbox. Accessibility is checked automatically (NF12). Offline field capture (FR25) keeps expiring drafts on the device and syncs them for review.

## Non-functional requirements

| ID | Status |
|----|--------|
| NF01 Isolation | **Done.** Isolation is enforced twice, once in the application and once in PostgreSQL row-level security (`ajgem/rls.py`). The application checks every route, and object keys are scoped per tenant. RLS is enabled and forced on all 20 tables. The API runs as a separate `NOBYPASSRLS` runtime role whose context (`app.user_id`, `app.org_id`) is set per transaction in `load_principal`. Organisation-scoped tables match on organisation. Project content additionally requires a live membership through `ajgem_visible_projects()`, and job tasks are visible only through a visible job. With no context the runtime role sees nothing. The runtime role has no UPDATE or DELETE on `audit_events`. The owner role is the documented bypass, used only for schema setup and maintenance tools, and the server refuses to start if its runtime role bypasses RLS. Tests: `test_rls.py` (9 database-level tests with app checks bypassed, plus a mutation check showing they fail without the policies), and the full suite also runs on PostgreSQL in CI. Queue workers read only job ids and creators with the owner role, then process each job on the runtime role with its creator's RLS context. **Adversarial tests** (`test_adversarial.py`, SQLite and PostgreSQL) put a hostile document in the asker's project, secrets in a sibling project and in another organisation, and a compromised model behind the adapter. They show that the model is only ever sent the asker's project excerpts; forged citations, out-of-range blocks, leaked figures and uncited claims are withheld; search and the threshold tool stay inside the project even with smuggled ids; instructions inside documents trigger no action; and a model cannot import another project's assay through extraction. |
| NF02 Identity | **Done (OIDC).** `AJGEM_AUTH_MODE=oidc` signs users in with the organisation's identity provider using authorisation code + PKCE, a public client, and state and nonce checks (`frontend/src/lib/auth.ts`). The API then verifies the ID token sent as a bearer token (`ajgem/auth.py`): signature against the provider's published keys (RS/ES/PS only, never `none` or HMAC, re-fetched on key rotation), issuer, audience, expiry and a maximum session age (12 hours by default). Accounts are never created by signing in: the first sign-in links the provider subject to the existing account with the same verified email, and the subject alone is used afterwards. **MFA** is read from `amr` (or a configured `acr`) and is required for administrator and reviewer operations (manage, review, resolve conflicts, audit), returning `MFA_REQUIRED` with a re-sign-in prompt. **Revocation** takes effect on the next request: deactivating a user, revoking a membership, or running `python -m ajgem revoke-sessions EMAIL`. In OIDC mode the development header and user picker are disabled. No secrets reach the browser bundle; the ID token is kept in session storage only. Tests: `test_auth.py` (10 tests, SQLite and PostgreSQL) and `frontend/e2e/oidc.cjs`, a browser run against a development-only mock provider, in CI. **Still to do:** each pilot's provider configuration and its MFA claim (some providers express MFA through `acr` or not at all),. **Refresh-token rotation:** when the provider returns a refresh token, the browser renews the ID token shortly before expiry and once on a 401. It uses each refresh token once and replaces it, shares one request between concurrent callers, and signs the person out when renewal is refused (reuse detection at the provider) or the subject changes. Renewal never extends a session past the server's maximum age from the original `auth_time`. Tested by `test_mock_oidc.py` (rotation and reuse revoking the family) and the e2e run with `MOCK_OIDC_TOKEN_TTL=70`. |
| NF05 Untrusted files | **Done (parsers).** Formulas, macros and external links are never executed, and file signatures are checked. PDF inspection, page parsing, rendering, OCR and CSV/XLSX reading run in a sandboxed child process (`services/sandbox.py`) with CPU-time, address-space and wall-clock limits and no network (fresh user and network namespaces where the kernel allows; recorded per page as `network_isolated`). The child returns plain data and has no database access. Limit hits flag the page (`PARSER_MEMORY_LIMIT`, `PARSER_CPU_LIMIT`, `PARSER_TIMEOUT`) or refuse the import, and are not retried. A **seccomp-BPF filter** (`services/seccomp.py`, x86_64 and aarch64, no extra dependency) then refuses syscalls a parser never needs: ptrace and cross-process memory access, the mount family, namespace changes, kernel modules, kexec, bpf, perf events, userfaultfd, keyrings, io_uring, clock and system changes, and every socket family except Unix. It also refuses syscalls from foreign ABIs (x32 and 32-bit compat), which would otherwise bypass it. The OCR engine still runs, because the filter is a deny list inherited by the processes the parser starts. Whether the filter was in force is recorded per page (`seccomp`), never assumed. Tests: `test_sandbox.py` (an INET socket and `unshare` are refused in the child, Unix sockets and subprocesses still work, and the BPF program is well-formed for both architectures). |
| NF14 Deployment integrity | **Done.** Dependencies are pinned. Alembic migrations (`0001` schema, `0002` RLS) run as the owner role, automatically on start-up or as an explicit step when `AJGEM_AUTO_MIGRATE=0`, in which case start-up refuses an out-of-date schema. Each migration runs in a transaction, so a failed migration leaves no partial changes on PostgreSQL. Tests cover drift detection between models and migrations (with a mutation check), downgrade and upgrade round trips (including the RLS revision), a single migration head, refusal of pre-migration databases, and stamping. CI runs the backend suite on SQLite and PostgreSQL, plus the frontend and browser checks. **Still to do:** staged releases and rollback runbooks for production. |
| NF04 Provider privacy | **Done for the answer adapter**. Each project has a `provider_policy` in its config revisions, and it defaults to off. An administrator must record the processing basis (retention, region, contract) before allowing external processing, and the change is audited. Only the excerpts retrieval selects are sent; database access and credentials are never sent. Audit events record the model, token usage and counts but not the evidence text. Still to do: per-organisation budgets and quotas (NF11). |
| NF11 Cost control | **Done.** Usage events record pages, OCR pages, model extraction and answer calls with tokens, and export bytes; storage is measured from stored versions; no evidence text is stored (`services/costs.py`, migration `0006`).
